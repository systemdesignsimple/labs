An index helps a database find rows without reading the whole table. Without an index, a query on a table of 1000000 rows may scan every row. A B-tree index keeps keys in sorted order, so a lookup only touches a few pages. Each index also has a cost, because every insert and update must change it too. A table with 8 indexes does more work on each write than a table with 1. Good indexes match the columns that real queries filter and sort on.
