An idempotent request has the same effect whether it runs once or many times. Payment systems often ask the client to send an idempotency key with each request. The server stores the key together with the result of the first attempt. If the same key arrives again, the server returns the stored result instead of charging twice. Keys are usually kept for a limited time, such as 24 hours. A retry after the key has expired can be treated as a brand new request.
